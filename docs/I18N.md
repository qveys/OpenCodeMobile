# Internationalization (i18n)

Cahier des charges §9.6 requires **FR + EN from V1**, the **device locale**, and
**no hardcoded user-visible string**. §13.2 lists "strings externalisées en FR et
EN" in the Definition of Done.

## Where the strings live

Compose Multiplatform resources are owned by the design system, which every
`features/*` module and the Android host already depend on (see
[`docs/ARCHITECTURE.md`](ARCHITECTURE.md) §6, "Localization"):

```
design-system/src/commonMain/composeResources/
├── values/strings.xml      # English (default / fallback)
└── values-fr/strings.xml   # French
```

The default catalog (`values/`) is English; `values-fr/` holds the French
translations. Both files must always define the same keys.

The module sets `publicResClass = true` and a stable package
(`org.opencodemobile.design.system.resources`) in `compose.resources { }`, so the
generated `Res` class can be consumed from other modules.

## Using a string

```kotlin
import org.jetbrains.compose.resources.stringResource
import org.opencodemobile.design.system.resources.Res
import org.opencodemobile.design.system.resources.app_name

Text(stringResource(Res.string.app_name))
```

From non-composable code use the suspending `getString(Res.string.…)`.

The CMP resource API resolves `Res.string.*` against the **device locale**
automatically; there is nothing to wire per screen. For an explicit mapping of
the device locale to a shipped language (for example to build an in-app language
selector later), use
[`AppLanguage`](../design-system/src/commonMain/kotlin/org/opencodemobile/design/system/i18n/AppLanguage.kt):
`AppLanguage.current()` / `AppLanguage.fromTag("fr-CA")`.

## Adding a string

1. Add the key to `values/strings.xml` **and** `values-fr/strings.xml`.
2. Use it via `stringResource(Res.string.<key>)`; never inline the literal.
3. The same catalog supports string templates (`%1$s`), string arrays and
   `<plurals>` (`pluralStringResource(Res.plurals.<key>, quantity, …)`) for when
   a screen needs them.

## Platform resources

Manifest/OS-level copy that cannot go through Compose lives in the platform
module: the Android app label is `androidApp/src/main/res/values{,-fr}/strings.xml`
(`@string/app_name`). The iOS SwiftUI shell in `iosApp/` is a non-built
placeholder and is replaced by the Compose host, which reuses this same catalog.

## Supported languages

FR and EN only for V1. No other locale is in scope.
